# 股票買賣點分析系統

React + Vite 單頁應用。**每檔股票使用一套獨立的、經回測驗證過的評分規則**，而不是共用一組通用指標權重。

打開頁面只需要看一件事：**今天該買、該賣，還是不動。**

---

## 目前支援的三檔

| 分頁 | 策略類型 | 買進依據 | 賣出依據 | 動作頻率 | 狀態 |
|---|---|---|---|---|---|
| **6669** 緯穎 | 長抱 + 過熱減碼 | RSI < 30（單一因素） | 季線乖離 > 30% 分級減碼 | 約 6.7 次/年 | 已驗證 |
| **2301** 光寶科 | 階梯加碼 + 賣訊清空 | 25 項評分 → 目標持倉張數 | 賣分 ≥ 80 全部清空 | 約 17 次/年 | 已驗證 |
| **3231** 緯創 | 短線波段（加權總分） | 布林 30% + 震盪 50% + 其他 | 同左，鏡像 | 依門檻而定 | ⚠️ **賣出側方向有問題，見下** |

> 頂部搜尋框可輸入任意台股代號建立新分頁，但**只有上表三檔有專屬驗證過的規則**；
> 其他代號會落到 6669 的規則上，不具參考價值。

## 各分頁策略說明

### 6669 緯穎（V25 — 單一因素）

**買進**：RSI（14 日 Cutler）低檔階梯，權重 100%
```
RSI < 25 → 100 分    RSI < 30 → 80 分 ★買進門檻
RSI < 40 →  50 分    RSI < 50 → 20 分    RSI ≥ 50 → 0 分
```
觸發條件：RSI **首次**跌破 30，且距上次買訊滿 **21 個交易日**（把頻率壓在每月最多一次）。

**賣出**：季線乖離階梯，權重 100%。**分級減碼、不清倉**（核心長抱）
```
乖離 > 40% → 減 1/2     乖離 > 30% → 減 1/3     乖離 > 22% → 預警
```

**為什麼只用一個因素**：對 10 個買進因素做系統性權重搜尋（2,607 組），以「訓練期選權重 → 測試期驗證」檢驗，訓練期第一名在測試期排名 2168/2607，訓練前 10 名的測試邊際（+2.27pp）**低於全部組合平均（+4.88pp）**——依訓練期挑權重比亂選還差。10 個因素中只有 RSI 低檔與 KD 低檔兩期都有效，其餘 8 個接近 0，混入只會稀釋訊號。

**已移除**：破線強制停損（跌破 Fibo 0.618）。實測跌破後 20 日平均 **+6.45%**（邊際 +3.26pp、t=4.07、兩期一致）—— 那是買點而非賣點。該規則在回測中把全期報酬由 +835% 壓到 +115%，最大回檔由 −50% 惡化到 −68%。

### 2301 光寶科（目標持倉制）

**核心規則只有三行：**
```
1. 應持有張數 = floor((今日買分 − 4) / 10) + 1        買分 < 4 → 0 張
2. 手上不足就補足差額；買分下降不賣（這是下限，不是目標值）
3. 賣分 ≥ 80 → 全部清空，不分批、無停損
```

| 今日買分 | 應持有 | 今日買分 | 應持有 |
|---|---|---|---|
| < 4 | 0 張 | 44~53 | 5 張 |
| 4~13 | 1 張 | 54~63 | 6 張 |
| 14~23 | 2 張 | 64~73 | 7 張 |
| 24~33 | 3 張 | 74~83 | 8 張 |
| 34~43 | 4 張 | 84~100 | 9~10 張 |

**買進評分：14 項等權（每項 7.14 分）**

| 族群 | 權重 | 因素 |
|---|---|---|
| 均線負乖離 | 35.7% | MA120 / MA60 / MA20 / MA10 / MA5 負乖離 |
| 自高點回落 | 21.4% | 自 60 / 20 / 10 日高點回落 |
| 跌幅動能 | 21.4% | 近 5 / 3 / 1 日跌幅 |
| 震盪超賣 | 21.4% | K9 低檔、K5 低檔、RSI5 低檔 |

**賣出評分：11 項等權（每項 9.09 分）**

| 族群 | 權重 | 因素 |
|---|---|---|
| 震盪超買 | 54.5% | RSI21 / RSI14 / RSI9 / RSI5 高檔、K9 / K5 高檔 |
| 均線正乖離 | 18.2% | MA60 / MA120 正乖離 |
| 相對位置 | 18.2% | 布林20 高檔、箱型高位 |
| 自低點反彈 | 9.1% | 自 60 日低點反彈 |

**為什麼「目標持倉制」而不是「一日買一張」**：App 無法記錄你實際持有幾張。目標持倉制每天從當日買分重新計算，不依賴任何歷史狀態 —— 實測**漏掉 50% 買訊，年損益只掉 10%**（一日一張的版本會掉 19%，因為漏一次就永久錯位）。而且它的動作更少（17 vs 23 次/年）、報酬更高。

**為什麼賣出用「別檔股票篩出來的」因素清單**：這 11 項在 2301 上的**前瞻邊際是負的**（訓練 −0.12 / 測試 −2.38pp）—— 2301 是動能股，超買之後往往還漲。但頻率對等檢定顯示：真買訊 + **隨機**持有天數 → CAGR 23.62%、勝率 62%；真買訊 + **真實**賣訊 → CAGR 32.4%、勝率 90%。**出場時機貢獻 +8.80pp（p = 0.0000）**。賣分的作用是「相對進場價鎖利」，不是預測未來下跌 —— 用前瞻報酬去挑賣出因素在這裡是錯的標準。

**為什麼等權**：買側對 5,562 組權重做系統性搜尋（全部單/雙/三因素 + 等權 + 4,000 組隨機 Dirichlet），訓練期最佳權重在測試期排名 **3592/5562**，各共識權重 K=1~500 全部落在 PR 50 附近 → 權重最佳化無效。賣側的訓練共識權重在測試期排名 5/4130（有效），但實際交易報酬反而低於等權清單。

### ⚠️ 3231 緯創：賣出側方向有問題

對 3231 的因素做兩期同向檢定（訓練期／測試期都需為正）：

| 側 | 通過兩期同向 | 邊際為正 |
|---|---|---|
| 買進（22 項） | 7 / 22 | 16 / 22 |
| **賣出（19 項）** | **1 / 19** | **3 / 19** |

賣出側 19 項中 **16 項邊際為負**，而目前的權重配置正好壓在最差的幾項：

| 因素 | 目前權重 | 實測邊際（訓練／測試） |
|---|---|---|
| 震盪過熱（RSI + KD） | 50% | RSI14高檔 **−0.802**、K5高檔 **−0.694**、RSI9高檔 **−0.636** |
| 布林高檔 | 30% | **−0.438** |
| MA20 正乖離 | 10% | **−2.211**（+1.164 / −2.382，兩期反向） |

**合計約 90% 的權重落在邊際為負的因素上** —— 意思是「清倉賣出」訊號實際上出現在還會繼續漲的位置。

買進側尚可用（MA60 負乖離 +2.957pp 兩期都正、MA20 +2.207、自60日高回落 +1.525）。

**目前狀態**：尚未修正。修正需要像 2301 那樣重跑完整的因素篩選與驗證。**在修正前請勿依賴 3231 分頁的賣出訊號。**

## 驗證方法

每一組規則在寫進程式前都經過以下檢定，未通過的規則不予採用：

| 檢定 | 目的 |
|---|---|
| **訓練/測試兩期同向** | 前後半期各自都要有正邊際，排除只在單一期間有效的因素 |
| **隨機化檢定** | 打亂訊號日 500~1000 次，實際績效必須優於隨機分布的 95 百分位 |
| **門檻高原分析** | 檢查最佳門檻的鄰域（±3~4 分）是否也全部有效，排除孤立尖峰＝過擬合 |
| **逐年連乘** | 逐年報酬相乘，避免單筆大獲利支配整體結論 |
| **只用前半期選門檻 → 後半期驗證** | 門檻選擇的樣本外檢定 |
| **排除近期多頭** | 檢查扣掉最近的大行情後是否仍為正 |
| **容錯測試** | 模擬漏掉 10~50% 訊號時的績效衰退 |
| **頻率對等的訊號價值拆解** | 分離「進場時機」與「出場時機」各自的貢獻 |
| **對照驗證（parity check）** | JSX 的計算結果必須與 Python 回測完全一致 |
| **資料源對帳** | Yahoo 價格逐日對照證交所 `STOCK_DAY` 官方收盤價，確認除權／分割調整一致 |

回測慣例：訊號用**前一日**收盤資料、成交用**當日開盤價**；台股手續費買賣各 0.1425%、賣出證交稅 0.3%（來回 0.585%）。

## 誠實的限制

1. **2301 的獲利集中在近年**。分期表現：2000~2009 每輪 +1.50%、2010~2014 +0.83%、2015~2020 +2.78%、**2021~2026 +13.75%**。這 25 項因素是用 2015 年之後的資料篩出來的，2000~2014 對它是樣本外且幾乎不賺錢（扣掉 0.585% 交易成本後接近零），2008 年有一輪滿倉 10 張虧損 −54.22%。**合理的長期預期請用每輪 +1~3%，不要用近年的 +13.75%。** App 的主要統計已限定 2015-07 起，分期表現完整揭露在 ⓘ 彈窗。

2. **使用未還原股價**。資料取自 Yahoo `indicators.quote.close`（不含息還原），所有乖離／回落／跌幅在除息日會出現假跌幅 → 假買訊。2301 實測：最差單輪從 −5.84%（還原）變成 **−12.07%**（未還原）。

   ⚠️ **注意這裡的「未還原」只指現金股息。除權（股票股利）Yahoo 是會回溯調整的**，兩者不要混為一談。6669 於 2026-09-02 除權，每股配股票股利 19.828 元（1 股配 1.9828 股，**是無償配股、不是股票分割**），證交所除權前收盤 7,800 → 參考價 2,614.99，價格調整因子 2.9828。實測 Yahoo 已把 2017-11 至今整段歷史除以 2.9828：對照證交所 2026-08 全月 21 個交易日，比值全距僅 3.2×10⁻⁷（TWSE 7,095 ↔ Yahoo 2,378.64）。因此：
   - **評分與訊號不受分割影響** —— RSI、乖離、KD、%B、箱型位階全部是比率，把序列同乘 2.9828 後重跑 V25，26 次買訊與 10 次減碼訊號的索引完全相同，RSI 最大差異 1.1×10⁻¹³。
   - **但畫面上的價格是還原後的新尺度**，與券商對帳單的舊價格不同（舊價 ÷ 2.9828）。
   - **「1 張」的資金量變成 1/3**（6669 分割前 1 張約 780 萬 → 現約 262 萬）。持股數變 2.98 倍、產生零股。減碼 1/3、1/2 是比例規則，不受影響。

   真正的風險是**調整不同步**：若資料源已登記分割事件、但價格序列還沒回溯調整，會出現人造斷點。實測 6669 若發生此情況，RSI 會由 82.4 被壓到 28.0、買分 0 → 80，**在最高點誤發「強力買進」**。因此程式加了守門（見下）。

3. **樣本量有限**。6669 的買訊只有 22 次、減碼 7 次；2301 有 45~50 輪。多重比較修正後 6669 的 p ≈ 0.034（勉強顯著）。

4. **不要重新最佳化門檻**。2301 實測「每年重新最佳化門檻」會讓連乘超額由正轉負（−50pp、勝 4/8 年），因為門檻會在買 10~24、賣 63~87 之間亂跳。固定門檻反而有 63/72 組勝 ≥5/8 年。

5. **策略對股票不可移植**。同一套邏輯在不同股票上方向可能相反 —— 6669 的賣出訊號是季線乖離（RSI 對它無效），2301 是震盪超買佔 54.5%（乖離只佔 18.2%），3231 的整個賣出方向是反的。

6. **停用條件**：連續 2 個完整年度虧損 → 停用；單輪虧損超過 −15% → 人工檢視；每年只做一次檢核，只決定是否繼續，**不改參數**。

## 資料來源與 CORS

資料來自 Yahoo Finance chart API（`indicators.quote[0].close`，除權已回溯調整、現金股息未還原）。

**Yahoo 不回 `Access-Control-Allow-Origin`，所以瀏覽器無法直連**，必須經過會補上 CORS 標頭的代理。這是本專案最脆弱的一環 —— 免費公共代理隨時改制、限流或停用。

### 2026-09-07 的全滅事故

當天使用者完全抓不到資料，逐一實測的結果是清單裡五個全部失效：

| 代理 | 實測結果 |
|---|---|
| `api.allorigins.win/get` | HTTP 522 Cloudflare 連不到源站，且**硬撐滿 20 秒**才回 |
| `corsproxy.io/?<url>` | HTTP 403 `keyless_legacy_url` — 已改制為需 API key |
| `api.allorigins.win/raw` | HTTP 522 / 520 |
| `cors.sh/<url>` | HTTP 404「CORS proxy temporarily paused」 |
| Yahoo 直連 | HTTP 200 有資料，但無 CORS 標頭 → 瀏覽器擋掉 |

配合當時的 20 秒逾時 × 5 個代理 × 3 輪重試，畫面要轉 **2 分 13 秒**才跳錯誤視窗。

已改為：`r.jina.ai` 為主（實測 1.9~4.5 秒取得三檔全歷史），逾時降到 9 秒、重試降到 2 輪（全滅時約 60 秒回報），並把「依代理索引硬編解析格式」改成**容錯解析**，四種包裝都能吃、代理回錯誤頁會被拒絕並自動換下一個。

### 長期解：自建 Cloudflare Worker（建議）

公共代理必然再掛一次。免費方案每天 10 萬次請求，遠超這個 App 的用量：

```js
export default {
  async fetch(request) {
    const target = new URL(request.url).searchParams.get('url');
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'GET,OPTIONS',
      'Access-Control-Max-Age': '86400',
    };
    if (request.method === 'OPTIONS') return new Response(null, { headers: cors });
    // ⚠ 一定要白名單，否則變成開放代理會被濫用而封鎖
    //   （公共代理 test.cors.workers.dev 就是這樣掛掉的，實測回 403 "banned for abuse"）
    if (!target || !/^https:\/\/query[12]\.finance\.yahoo\.com\//.test(target)) {
      return new Response('bad url', { status: 400, headers: cors });
    }
    const r = await fetch(target, { headers: { 'User-Agent': 'Mozilla/5.0' } });
    return new Response(r.body, {
      status: r.status,
      headers: { ...cors, 'Content-Type': 'application/json', 'Cache-Control': 'public, max-age=300' },
    });
  },
};
```

部署後把它插到 [App.jsx](src/App.jsx) `proxyServices` 的**第一個**：

```js
{ name: 'Cloudflare Worker (自建)',
  func: (url) => `https://<你的worker>.workers.dev/?url=${encodeURIComponent(url)}` },
```

### 為什麼不改用證交所官方 API

證交所 `STOCK_DAY` **有 CORS 標頭**、速度也夠（實測 0.09 秒/月，2301 全歷史 320 個月約 30 秒），但它回的是**未還原的實際成交價**：

```
115/09/01 收 7,800.00
115/09/02 收 2,610.00   ← 除權造成 −66.5% 斷點
```

三檔幾乎每年 8 月都會出現這種斷點，所有指標會被汙染（見下方「資料完整性守門」）。要用它就得自行維護全部歷史除權因子，而那些因子本身還是得從 Yahoo 來。因此 Yahoo 仍是唯一提供連續序列的來源，問題只在 CORS。

## 資料完整性守門

三檔共用一道檢查：若**最近 10 根 K 線**出現單日變動超過 **±11%**，主頁最上方會跳出琥珀色警示，明確要求當日評分與訊號不要採用。

台股單日漲跌幅上限是 ±10%，所以越限幾乎只有一個成因 —— 資料源登記了除權／分割事件、但還沒把調整套用到整段歷史。這種汙染會同時打壞所有指標，而且錯誤方向通常是**在高點誤發買進訊號**（見限制 2 的實測數字）。3231 與 2301 幾乎每年 8 月除權（歷史上分別有 15、18 次分割事件），每年都會經過一次這個風險窗口。

只檢查最近 10 根，是因為更早的資料可能來自興櫃（無漲跌幅限制，6669 在 2018 年有 12 天正當越限）或 2015 年前的 ±7% 制度期。誤報驗證：三檔各取最近 1,250 個交易日逐日模擬，觸發 **0 次**；歷史越限日最晚出現在 2018-11-15，遠在 10 根視窗之外。

實作在 [App.jsx](src/App.jsx) 的 `dataAlert`。

## 使用說明

1. 頂部搜尋框輸入代號建立分頁（預設 6669 / 3231 / 2301）
2. **最上方的「今日動作」卡就是結論** —— 其餘都是輔助
3. 2301 分頁：在決策卡輸入你目前持有幾張，會算出該補幾張（不會被記錄，每次自行輸入）
4. 買/賣評分卡的 ⓘ 有完整的因素明細、階梯規則與驗證數據
5. 2301 決策卡右上的 ⓘ 有全期統計、分期表現、停用條件
6. 圖表右上可切換顯示區間（1年 / 2年 / 5年 / 全部）—— **只影響顯示，評分一律用完整歷史**
7. 點下方指標小卡可切換圖表疊圖；卡片上的 🟢（買方因素）／🔴（賣方因素）／⚪（不列入評分）標示該指標在當前分頁的角色
8. 若最上方出現**琥珀色「資料異常」警示**，代表資料源的除權／分割調整還沒同步，當日評分與訊號一律不要用，隔一個交易日重新整理再看
